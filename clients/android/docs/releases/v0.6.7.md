# DSH for Android v0.6.7

Any picture in the app now opens full screen — paged, zoomable, and with a way out that a
screen reader can reach. `![alt](url)` also renders in the transcript, where it used to be
alt text and a promise the parity ledger had been carrying as a gap.

## The picture is the control

Tapping a picture raises the viewer. That is the web's rule — its original-image preview opens
on a click of the thumbnail — and a phone has no hover to hide a second affordance behind, so
the picture itself is the button everywhere it appears:

- a message's image attachment, and the other pictures **of that message**;
- a `read_image` card's images, paged as that card's own set;
- an inline `![alt](url)` picture, whenever it resolved;
- a raster preview in the Files pane, paged through the rasters of the list it was reached
  from — the session's files, or the directory Browse is showing. The two lists spell paths
  differently, so a set never mixes them. SVG is left out: it is drawn from markup, not
  decoded as a bitmap. The file *row*'s tap still selects, as before.

A thumbnail that failed to load opens too, because the viewer is where the reason and the
Retry are.

## One overlay, at the window root

The viewer is composed once, above every screen surface, so its black backdrop covers the chat
header and the Files panel rather than stopping at the transcript's box. It takes the pointer
away from what is underneath instead of trusting that nothing below will react: without that, a
dismissal drag also scrolled the transcript, which the reader only noticed after closing.

It closes by the system Back gesture, its close control, a tap on the backdrop outside the
picture, or a downward drag. Escape has no meaning here; Back is the same dismissal.

## Zoom and pan are arithmetic, not vibes

Pinch zooms between fit and 5×, double-tap toggles 2.5×, and the pan is clamped *per axis* to
the overflow — so a tall portrait can be panned vertically while staying centred horizontally,
and a fitted picture cannot be dragged off into empty space at all. Pinching recomputes the pan
about the fingers' centroid, so the point under them stays put instead of sliding out from
under the gesture.

The limits live in `model/Lightbox.kt` with no Android types and are covered by
`model/LightboxTest`, which is where a threshold can be argued with; the composable keeps only
the gesture recognition and the drawing.

At fit, a horizontal drag pages and a downward drag dismisses; upward travel is swallowed
rather than moving the picture. While zoomed, both are pan — a downward drag never closes out
from under someone inspecting an edge.

Paging is a swipe with an `N of M` counter only when there is more than one picture: "1 of 1"
is the chrome that makes a viewer feel busier than the photograph.

## A picture that will not load says why

The loader used to answer `null` for every way an image can fail, and the row drew the same
grey block for all of them. The viewer has room for the sentence, so the answer is now
`ImageLoad` — pixels or a reason — and the reason is drawn under the title: no open session, a
refused read with the host's own message, bytes this device cannot decode, an answer above the
2 MiB preview ceiling. Retry is offered because most of these are a dropped connection or a
file replaced mid-read, not a permanent fault.

## Inline images

`![alt](url)` renders in messages, reasoning, tool output and the Files pane's Markdown view.
An `https://` address is fetched with no credentials, no cookies of its own and **no redirect
at all** — a 3xx is reported as its status, because an address a model wrote is not a reason to
land the call on a different host. Anything else is a path in the session's workspace, read
through the same `workspaceFiles/readBytes` the Files pane uses.

The ceiling holds even for a chunked answer that declares no length: the body is requested one
byte past the limit and refused unread. The decoded-bytes cache is bounded by bytes (8 MiB)
rather than by picture count, which had allowed 24 entries of up to 2 MiB. A picture that will
not resolve keeps its alt text, which is the web's fallback as well.

## Saving

Where a page has a workspace path — a Files preview, a markdown path — the viewer carries the
Files header's own Download control, so a save goes through the one download and save-dialog
path in the app. An attachment page has an attachment id and no path, and the web's lightbox
offers neither download nor zoom at all; both are noted as gaps in `docs/PARITY.md` rather than
quietly absent.

## Not verified here

Gesture *recognition* — that a pinch arrives as a pinch, that the transcript's scroll does not
steal a drag, that a downward pull is not taken by the system — is device work. Robolectric's
clock and stub display make a synthesised swipe a statement about the harness, so the touch
rules are pinned as arithmetic and the recognition is left to a finger. The web restores focus
to the opener on close; this app focuses the close control on open — the one target a TalkBack
user is left with — and leaves focus to Compose when the overlay goes away.
